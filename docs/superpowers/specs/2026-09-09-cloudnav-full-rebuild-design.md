# CloudNav 全面重构设计

日期：2026-09-09

## 目标

将 CloudNav 从“单文件驱动的链接导航”升级为“桌面优先的个人信息工作台”，让置顶网站、工作台和 RSS 资讯成为三个清晰、连续、可扩展的主空间。

本次重构优先解决四件事：

1. 电脑端布局层级混乱，页面之间像两套产品。
2. `App.tsx` 同时承担壳层、数据、路由、弹窗和业务动作，修改成本高。
3. 首屏依赖多组远程数据，打开后需要等待内容逐步出现。
4. RSS、书签、工作台能力已经存在，但缺少统一的信息架构和交互语言。

## 参考项目与取舍

本次只参考公开项目的产品结构和工程思路，不复制代码或视觉资产。

- [gethomepage/homepage](https://github.com/gethomepage/homepage)：参考“快速搜索 + 服务/书签 + 小组件”的首页信息密度，以及静态生成优先的加载思路。CloudNav 不采用 YAML 作为用户数据源，而继续保留现有云端与本地数据。
- [sissbruecker/linkding](https://github.com/sissbruecker/linkding)：参考极简书签管理、标签和快速搜索的产品边界。CloudNav 保留分类、置顶、回收站和批量操作，但不把首页变成管理后台。
- [miniflux/v2](https://github.com/miniflux/v2)：参考 RSS 的后台刷新、缓存、ETag/Last-Modified、阅读状态、OPML 和键盘操作方向。CloudNav 首期继续使用现有 RSS API，并优先完善缓存、来源状态和空内容处理。
- [reminiflux/reminiflux](https://github.com/reminiflux/reminiflux)：参考桌面端三栏阅读的空间关系。CloudNav 将其简化为“来源栏 + 文章流 + 阅读抽屉”，避免在当前数据规模下引入过重的阅读器复杂度。
- [MarioGervais/open-airss](https://github.com/MarioGervais/open-airss)：参考主题、键盘导航和内容优先的 RSS 阅读体验。CloudNav 只保留中文内容筛选、收藏、标记已读和来源管理等与当前产品一致的能力。
- [songshiqiang/bookmark-dashboard](https://github.com/songshiqiang/bookmark-dashboard)：参考将文件夹转成卡片入口的方式。CloudNav 仅在工作台展示少量分类快捷入口，置顶网站页不再堆叠全部链接。

## 产品信息架构

### 1. 置顶网站

这是打开网站后的默认页。

- 只展示 `pinned` 链接和用户明确标记为常用的入口。
- 保留搜索、分类筛选、排序、批量编辑和添加入口。
- 不展示全部链接网格；全部链接通过分类目录和搜索进入。
- 桌面端使用稳定的多列卡片网格，卡片内容优先于装饰。
- 空状态提供“添加置顶入口”和“前往分类目录”两个动作。

### 2. 工作台

工作台是独立页面，不与置顶网站混合。

- 顶部为页面标题、搜索入口和工作台状态。
- 中部为最近访问、今日专注、分类快捷入口。
- 下部为待办、快捷笔记、Markdown 和天气工具。
- 组件可隐藏和排序，配置继续持久化。
- 工作台只展示少量高频入口，避免复制置顶网站的全部内容。

### 3. RSS 资讯

RSS 是独立的一等页面。

- 左侧或顶部显示中文来源、主题筛选和未读数。
- 中间显示文章流，支持时间、来源、未读和关键词过滤。
- 右侧抽屉或阅读区显示正文摘要、来源、发布时间和外链。
- 无内容来源显示可解释的状态：暂无文章、抓取失败、等待刷新，而不是空白卡片。
- 继续支持 OPML 导入/导出和订阅源自动发现。
- 默认只保留中文 AI、GitHub、科技和产品类订阅，英文源不进入默认推荐。

## 应用架构

### Shell 层

新增以下边界，逐步从 `App.tsx` 迁出布局职责：

- `AppShell`：页面根布局、主题和响应式容器。
- `DesktopSidebar`：主导航、分类目录和底部工具。
- `TopCommandBar`：搜索、视图模式、同步状态、添加入口。
- `MobileBottomNav`：移动端五项导航。
- `PageContainer`：页面宽度、滚动、空状态和过渡边界。

### View 层

将三个页面明确拆分：

- `PinnedSitesPage`
- `WorkbenchPage`
- `RssPage`

每个页面只负责展示和页面动作，通过 props 或小型 controller 接收数据，不直接读取大量全局状态。

### State 层

增加轻量的页面状态边界，不引入新的状态管理库：

- `useAppBootstrap`：本地快照、认证检查、云端补水和错误状态。
- `useLinksData`：链接、分类、置顶、搜索和访问记录。
- `useWorkbenchState`：工作台模块配置和工具数据。
- `useRssState`：来源、文章、筛选、刷新和阅读状态。
- `useCommandActions`：命令面板和顶部快捷动作。

现有 service 文件继续作为数据访问层，组件不直接拼接 API 请求。

### 数据加载流程

```text
启动
  -> 读取本地快照
  -> 立即渲染置顶网站
  -> 并行检查认证 / 拉取云端链接 / 拉取配置
  -> 合并并校验数据
  -> 局部刷新页面
  -> RSS 与设置模块按需加载
```

要求：任何单个配置请求失败，都不能阻塞置顶网站首屏；RSS 接口异常只影响 RSS 页面，不影响导航和工作台。

## 视觉系统

### 设计方向

采用“轻量个人控制台”风格：蓝白底、低对比阴影、清晰分区、少量强调色。保留当前品牌色，不再引入第二套深色或高饱和 UI。

### 桌面端基准

- 左侧导航宽度约 240–256px。
- 顶部操作栏高度约 64px。
- 内容最大宽度约 1440–1600px，并自动居中。
- 页面间距使用 8px 基础网格，常用分组间距 16/24/32px。
- 卡片统一圆角、边框、悬停、焦点和禁用状态。
- 主体文字不低于 12px，正文和辅助信息保持可读对比度。

### 动效原则

- 页面切换使用空间连续过渡，时长 180–360ms。
- 卡片只做轻微位移和边框反馈。
- 不使用全屏炫光、持续旋转或大面积弹跳。
- 支持 `prefers-reduced-motion`，关闭非必要动画。

## 兼容与迁移

- 保留现有 `localStorage` key、Cloudflare KV 字段和备份格式。
- 新增字段必须提供默认值和旧数据归一化。
- 迁移失败时回退到只读本地快照，不清空用户数据。
- 现有认证、WebDAV、备份、回收站、重复检测和健康检测功能不删除。
- 当前未提交的用户改动不通过重构覆盖或清理。

## 实施阶段

### Phase 1：壳层和数据启动链路

拆出 `AppShell`、顶部栏、桌面侧栏和 `useAppBootstrap`，保证默认页立即显示本地快照。

### Phase 2：置顶网站页

迁移现有链接页为 `PinnedSitesPage`，固定“只显示置顶/常用”的产品边界，统一卡片网格和空状态。

### Phase 3：工作台页

迁移 `HomeDashboard` 为 `WorkbenchPage`，保留模块排序、隐藏和工具持久化。

### Phase 4：RSS 页

迁移 `RssReaderPage` 为 `RssPage`，补齐来源状态、文章阅读、缓存和错误边界。

### Phase 5：统一组件与清理

统一按钮、卡片、抽屉、弹窗、加载、错误和空状态；删除迁移后不再使用的重复布局代码。

### Phase 6：验证与部署准备

运行类型检查、全量测试、性能测试、生产构建和浏览器 smoke test，确认桌面端宽屏、窄屏和深色模式均可用。

## 验收标准

1. 打开网站立即看到置顶网站，不等待远程配置。
2. 置顶网站页不出现所有链接网格。
3. 工作台、置顶网站和 RSS 页面使用同一套应用壳层。
4. 桌面端布局在 1024px、1440px、1920px 宽度下稳定。
5. RSS 空内容、失败、刷新和无订阅状态都有明确反馈。
6. 旧链接、分类、配置、备份和本地缓存可以继续使用。
7. 全量测试、性能测试、类型检查和生产构建通过。
8. 不新增英文默认订阅，不把用户凭据写入前端或备份明文。
