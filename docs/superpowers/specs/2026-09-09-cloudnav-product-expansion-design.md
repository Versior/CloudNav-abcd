# CloudNav 全量产品升级设计

## 目标

在保持现有视觉风格、默认进入「置顶网站」和 Cloudflare 部署方式不变的情况下，完善性能、安全、健康检测、搜索、工作台、PWA 与移动端体验。

## 方案

### 性能与 PWA

- 为首屏、设置、备份、图表与工作台工具设置稳定的 Rollup 分包边界。
- 首屏继续只加载置顶网站所需代码；安装 PWA 时提供轻量提示，不缓存 API 或认证结果。
- 移动端提供底部导航和快捷添加入口，避免依赖桌面端顶部操作区。

### 安全与数据

- 登录失败按 IP 做短期 KV 限流，成功登录清理失败计数。
- 自动备份继续复用已有版本历史，并增加本地恢复快照，最多保留最近 5 份。
- 重复链接清理统一走回收站，保留恢复链路。

### 健康检测

- 前端健康请求增加有限次数、指数退避重试。
- Cron 识别失效恢复，并通过已有 Webhook 通知。
- 重复链接合并采用“保留项优先 + 补齐空字段 + 标签并集”的纯函数规则。

### 搜索与工作台

- 建立内存搜索索引，索引标题、URL、描述、备注、标签、别名和账号元数据。
- 搜索结果把健康状态、置顶和访问频率纳入排序。
- 工作台新增时钟、天气、待办、快捷笔记和 Markdown 模块，数据保存在本地并可随备份导出。

## 测试与边界

- 所有业务规则先写 Node `node:test`，先看到失败再实现。
- 浏览器能力（PWA 安装、地理位置、IndexedDB）必须有无权限/不可用时的降级路径。
- 天气只在用户主动点击后请求，失败时不影响导航使用。
- 完成后执行全量测试、类型检查、生产构建、性能测试和线上 HTTP 验证。
