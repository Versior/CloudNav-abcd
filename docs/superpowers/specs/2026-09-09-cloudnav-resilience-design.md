# CloudNav 韧性升级设计

## 目标

在保持现有 UI 风格和“置顶网站”默认入口不变的前提下，补齐四项数据可靠性能力：回收站、三方同步合并、失效链接通知、离线写入队列。

## 设计

1. **回收站**：删除改为软删除，保留 `deletedAt`，主列表过滤已删除项；设置中增加回收站面板，支持恢复和永久删除，永久删除前二次确认。
2. **三方合并**：以最近一次成功云端快照为 base，对 local/cloud 按 ID 和字段做三方合并；一方未改动时直接取另一方，双方都改动时按更新时间优先，否则保留本地值并显示冲突数量。
3. **失效通知**：健康检测设置增加可选 HTTPS Webhook。Cron 仅在本次新增确定失效链接或失效数量上升时通知，失败不阻断健康扫描。
4. **离线队列**：优先使用 IndexedDB 保存待同步 mutation，并保留 localStorage fallback；同一时刻只保留最新快照，恢复在线后按当前云版本重试，仍冲突交给三方合并。

## 数据流与边界

- 本地 UI 先更新并写入本地缓存，云端写入失败只进入队列，不阻塞点击和页面渲染。
- 回收站数据仍包含在云端 `app_data` 和版本历史中，避免误删不可恢复。
- Webhook URL 必须为公共 HTTP(S) 地址，不允许凭据、localhost、内网 IP 或跳转到内网。
- API 配置接口继续沿用现有认证；健康通知配置仅认证后可读写。

## 测试策略

- 纯函数先用 Node `node:test` 覆盖软删除、三方合并、通知触发条件、离线队列合并。
- 静态 UI 测试检查设置入口、回收站文案、三方合并和 IndexedDB 接线。
- 完成后执行 `npm.cmd test`、`npm.cmd run typecheck`、`npm.cmd run build`、性能测试和部署后的 HTTP 检查。
