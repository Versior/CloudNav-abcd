# CloudNav 空间连续动效重构设计

## 目标

在保留现有 CloudNav 功能、数据结构和中文产品定位的前提下，建立一套统一的“空间连续”动效系统，解决工作台、置顶网站、RSS 和弹窗之间像两套产品的问题。

动效的重点不是持续漂浮或炫光，而是让用户理解“我从哪里来、现在在哪里、下一步会到哪里”。页面之间共享位置、层级和方向，形成一张连续的工作画布。

## 已确认的设计方向

- 主方向：空间连续。
- 保留现有蓝白视觉基调，不再新增第二套完全不同的主题。
- 动效服务于导航、状态和内容层级，不作为装饰背景持续播放。
- 所有页面共享同一套时长、缓动、层级和减少动态效果规则。

## 核心体验

### 1. 页面切换

工作台、置顶网站和 RSS 视为同一工作区的三个视图，而不是互相独立的页面。

- 侧栏当前项的选中背景向主内容标题区域连续延展。
- 主内容容器保留稳定的边界和滚动位置，只对发生变化的区域做位移与透明度过渡。
- 视图切换使用 240–360ms 的空间方向过渡：进入内容时向前展开，返回时向后收束。
- 不使用整页白屏、从中央突然淡入或大幅弹跳。

### 2. 网站卡片到详情

网站图标、标题和分类标签作为共享元素参与过渡。

- 点击卡片后，图标和标题先保留原位，再移动到详情抽屉或详情面板的对应位置。
- 详情面板从触发卡片所在方向展开，避免所有弹窗都从屏幕中心出现。
- 关闭详情时沿相反路径回收，返回后原卡片仍保持可识别的位置。

### 3. RSS 阅读

RSS 列表、文章预览和原文入口使用同样的空间关系。

- 列表卡片的来源标识和标题进入文章预览头部。
- 文章阅读区从列表所在列展开，保留来源、发布时间和返回路径。
- 刷新和空状态只更新内容区域，不重新动画整个页面。

### 4. 工作台模块

工作台模块不再各自使用不同的卡片动画。

- 最近访问、高频链接、待办和快捷入口使用同一层级模型。
- 模块进入时只允许有限的 20–40ms 错峰，最多展示两层，避免整页级联飞入。
- 模块拖动、展开和收起使用同一套深度阴影与占位逻辑，减少布局跳动。

## 动效令牌

```ts
export const motionTokens = {
  fast: 160,
  normal: 260,
  spatial: 360,
  stagger: 28,
  easeSpatial: 'cubic-bezier(0.22, 1, 0.36, 1)',
  easeExit: 'cubic-bezier(0.4, 0, 1, 1)',
};
```

约束：

- 优先使用 `transform`、`opacity` 和 `filter`，避免动画中修改布局尺寸。
- 进入动画比离开动画更完整，离开动画更快，减少等待感。
- 单个交互的位移保持在 4–24px 以内；不使用无意义的连续旋转。
- 所有动效必须在 `prefers-reduced-motion: reduce` 下关闭或降级为瞬时状态切换。
- 初次加载不播放整页入场动画，首屏先显示结构和缓存内容，再局部替换数据。

## 统一页面结构

重构时只保留一套共享壳层：

- 左侧导航：品牌、工作台、置顶网站、RSS 和分类入口。
- 顶部工具栏：搜索、筛选、主题、退出和添加入口。
- 主内容区：页面标题、上下文操作、内容面板。
- 详情层：统一使用从触发源展开的抽屉或侧面板。

工作台和置顶网站可以有不同的内容布局，但不再使用两套不同的顶部、侧栏、卡片边界和动效语言。

## 性能与实现边界

- 不引入新的动画框架；优先使用现有 React 和 CSS 能力。
- 不修改链接、RSS、健康检测、备份和同步的数据模型。
- 不在首屏等待远程数据完成后才绘制页面；沿用缓存优先、后台刷新策略。
- 长列表使用局部更新，避免因为单条数据变化导致整页重新渲染。
- 开发阶段用浏览器验证工作台、置顶网站、RSS、详情抽屉、设置弹窗和移动端导航。

## 验收标准

1. 工作台、置顶网站和 RSS 使用同一套页面壳层和动效令牌。
2. 页面切换能明确体现方向和层级，但不会出现整页闪白、跳动、弹跳或持续漂浮。
3. 点击网站卡片和 RSS 条目时，图标或标题至少有一个共享元素连续到详情层。
4. 关闭详情后能沿原路径回到原卡片位置，滚动位置不丢失。
5. 首屏优先显示缓存结构，数据更新不会让页面整体重新播放动画。
6. `prefers-reduced-motion` 开启时仍能完整使用所有功能。
7. 现有测试、生产构建和移动端布局保持通过。

## 分阶段实施

### 阶段一：建立统一壳层与令牌

抽取共享布局、动效令牌、页面过渡和详情层基础组件，先接入工作台与置顶网站。

### 阶段二：接入 RSS 与交互细节

将 RSS 列表、文章预览、搜索、筛选、弹窗和抽屉迁移到同一套空间连续规则。

### 阶段三：性能和可访问性收尾

补齐减少动态效果、焦点管理、缓存优先首屏、列表局部更新与构建验证。
