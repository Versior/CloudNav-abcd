# CloudNav 工作台布局优化设计

## 目标

在不改变现有蓝白视觉方向、功能和默认入口的前提下，降低工作台的信息噪声，让用户打开页面后先看到“最近访问”和“常用入口”，再看到统计、待办和笔记。

## 设计决策

### 1. 页面层级

- 页面外层不再使用厚重的渐变大容器，改为轻背景 + 独立面板。
- 顶部保留工作台标题、说明、当前时间和自定义模块入口。
- 数据概览从四张等权卡片调整为三张紧凑指标卡：总链接、已访问、异常链接；待整理仍通过醒目的操作入口呈现。
- 文件夹从整行大面板调整为横向紧凑入口条，点击后仍进入对应分类。

### 2. 内容布局

- 主列展示最近访问，保留完整链接标题、分类和访问时间。
- 侧列展示高频链接和待办事项，形成“查看—行动”的顺序。
- 底部并排展示快捷笔记和 Markdown，减少工具模块对主内容的干扰。
- 保留原有自定义模块开关与上下排序能力；模块数据、回调和持久化逻辑不变。

### 3. 响应式与无障碍

- 桌面端采用主列 + 侧列布局；中等宽度堆叠内容列；移动端单列展示并保持触控目标可用。
- 图标只用于辅助识别，按钮继续使用可读文本或 aria 标签。
- 不新增横向页面滚动；文件夹入口在窄屏下可横向滚动。
- 保留深色模式的现有颜色语义。

### 4. 边界

- 不更换产品名称、导航结构、数据模型和工作台功能。
- 不新增第三方 UI 依赖。
- 不修改置顶网站页面行为。

## 验收标准

- 工作台首屏明显减少大块空白和重复边框。
- 最近访问成为视觉主焦点，高频链接、待办、笔记和 Markdown 分层明确。
- 点击文件夹、链接、待整理和自定义模块的现有交互继续有效。
- 现有全量测试、类型检查和生产构建通过。
