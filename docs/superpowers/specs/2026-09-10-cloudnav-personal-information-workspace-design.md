# CloudNav 个人信息工作台升级设计

## 背景

CloudNav 已经具备桌面优先的导航、RSS 阅读、健康检测、备份、搜索与天气基础，但信息仍分散在不同页面，用户无法把 RSS、链接、灵感和稍后处理内容串成一条工作流。本次升级保持现有导航、RSS 数据和 Cloudflare 部署不变，不再引入内嵌网页或重复的卡片容器。

## 产品定位

将 CloudNav 定位为“个人信息工作台”：先收集，再阅读，再提炼，最后沉淀为可搜索的灵感或入口。电脑端是主体验，移动端只保留快捷入口和核心浏览。

## 信息架构

- 工作台：今日待办、最近收集、未读与稍后阅读入口。
- 置顶网站：只展示置顶入口，不改变现有默认页。
- RSS 资讯：订阅源、文章列表、阅读详情、收藏、稍后阅读和 AI 摘要。
- 灵感库：快速记录灵感、网页、引用和待处理内容，支持 Markdown、标签、搜索和状态。
- GitHub：跟踪仓库、版本更新和 README 摘要，先支持手动添加与刷新，避免依赖 GitHub Token。
- 网站库：保留现有分类和排序能力。
- 设置：备份、健康检测、AI、RSS 订阅编辑与数据恢复。

## 第一阶段交付范围

1. 建立本地优先的灵感数据模型和服务，支持新建、编辑、删除、归档、标签与来源链接。
2. 增加桌面端灵感库页面：左侧筛选、中央时间线、右侧编辑/详情，不使用标签网格作为主布局。
3. 增加全局“快速记录”入口：从顶部命令栏、工作台和 RSS 文章进入，自动带入标题、链接与来源。
4. 增加稍后阅读服务：RSS 文章、网站和 GitHub 项目可以统一加入，支持状态和去重。
5. 增加 GitHub 追踪页面的基础版本：手动添加仓库、刷新仓库元数据、显示 README/描述，并允许转为灵感或稍后阅读。
6. 把新增数据纳入本地 JSON 备份与恢复；现有链接/RSS 恢复流程保持兼容。

## 第二阶段边界

- AI 摘要只在用户点击时执行，缓存结果，失败不影响阅读；RSS 使用现有中文事实核对提示词。
- 统一搜索先覆盖链接、RSS 文章、灵感和稍后阅读，沿用现有搜索框与命令面板，不再增加第二套搜索框。
- 自动化先提供可持久化的刷新记录和手动刷新入口，定时任务继续沿用现有 Cloudflare Worker 基础。

## UI 规则

- 桌面使用“窄侧栏 + 中央内容 + 右侧上下文”的连续工作区。
- 不嵌入第三方网页，不在一个页面里堆叠重复内框。
- 文章标题、正文、来源和状态使用明显的文字层级；控件优先使用文字按钮而不是只显示图标。
- 详情面板固定在阅读区内，滚动只发生在主内容列，避免右侧空白和文章滚出视口。
- 颜色沿用现有深色侧栏与浅色内容区，但只保留一种主阴影和一种强调色。

## 数据模型

`Inspiration`：`id`、`title`、`content`、`type`、`tags`、`sourceUrl`、`sourceTitle`、`status`、`createdAt`、`updatedAt`、`archivedAt?`、`aiSummary?`。

`ReadLaterItem`：`id`、`kind`、`title`、`url`、`source`、`summary?`、`status`、`addedAt`、`updatedAt`。

`GithubWatchItem`：`id`、`owner`、`repo`、`url`、`description?`、`stars?`、`language?`、`lastRelease?`、`readme?`、`lastFetchedAt?`、`error?`。

数据通过独立 localStorage key 保存，备份 envelope 使用可选字段以兼容旧备份。

## 验证

- 先为纯服务写 Node `node:test`：数据归一化、CRUD、去重、备份兼容与 GitHub URL 解析。
- 再写页面静态契约测试：导航、快速记录、RSS/网站/GitHub 转入灵感和稍后阅读。
- 完成后运行全量测试、类型检查、生产构建、性能测试，并验证本地与 Cloudflare 页面返回 200。
